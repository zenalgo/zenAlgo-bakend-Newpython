🚀 Architecture & End-to-End Pipeline

[ Frontend Builder ] ---> [ POST /api/strategy (Dual Persistence) ] ---> [ State: WAITING ] │ [ POST .../activate ] ---> [ State: MONITORING_ENTRY ] │ [ Live Market Tick / 5m Candle Event ] │ [ Strategy Router ] │ [ Golden Rule Condition Met ] │ [ Signal Engine (SIG-*) ] │ [ Risk Engine Approval ] │ [ Execution Validator (Hedge Guard) ] │ [ Batch Execution Engine (PAPER) ] │ ┌─────────────────┴─────────────────┐ [ Success: Position OPEN ] [ Failure Trace Logged ] │ [ ExitEngine (2R / SL / 15:15) ] │ [ Square-Off: Position CLOSED ]

Idempotency & Safety: Every strategy execution is fully isolated and auditable. State transitions are strictly controlled via StrategyStateManager. The platform defaults to PAPER trading for maximum capital protection.

1. Strategy Management & Builder APIs (Frontend)

POST /api/strategy   or   /api/v1/strategies   or   /api/v1/admin/strategies Schema v2.0.0

Creates a new strategy with dual relational persistence and complete JSON builder configuration.

Why We Use This API: Triggered when the user or administrator clicks "Save Strategy". It ingests the frontend payload (whether flat or wrapped with config), creates the root Strategy entity, provisions an immutable StrategyVersion (v1), extracts execution legs, and sets runtime state to WAITING.

GET /api/strategy/{id}   or   /api/v1/strategies/{id}

Retrieves the complete un-truncated strategy configuration with all original builder fields.

Why We Use This API: Used by frontend edit and view screens to reload all 4 option legs, Camarilla pivots, earnings blackout windows, and risk limits.
Request cURL:
curl -X GET "http://localhost:8000/api/strategy/1042" -H "Authorization: Bearer YOUR_TOKEN"
POST /api/strategy/{id}/activate   or   /api/v1/strategies/{id}/activate

Deploys the strategy into autonomous paper trading.

Why We Use This API: Triggered when user clicks "Deploy Paper Trading". Moves state from WAITING → MONITORING_ENTRY and registers with the live market data router.
Request cURL:
curl -X POST "http://localhost:8000/api/strategy/1042/activate" -H "Authorization: Bearer YOUR_TOKEN"

2. Admin Execution Tracking & User Tracing APIs

GET /api/v1/admin/execution/strategies/{strategy_id}/batches Auditing & Analytics

Track how many users executed for a strategy across different signals and trading dates.

Why We Use This API: Answers "How many subscribers executed this strategy?". Displays total subscribers, eligible users, successful fills, failures, and batch completion timestamps.

GET /api/v1/admin/execution/batches/{batch_id}/traces

Lists all user execution traces for a specific batch (filterable by ?status=FAILED).

Why We Use This API: Shows admin all users in a trade batch with their current step, status (EXECUTED, FAILED, REJECTED), and failure reasons.
Request cURL:
curl -X GET "http://localhost:8000/api/v1/admin/execution/batches/5501/traces?status=FAILED" \
  -H "Authorization: Bearer YOUR_ADMIN_TOKEN"
